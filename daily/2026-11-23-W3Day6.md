# 2026-11-23（W3 Day6 · 缺陷管理）


**做了什么**：学习 bug 生命周期（五主状态+三异常分支）、严重程度vs优先级区别、bug 报告八要素；四个练习全做并验收通过（练习2和3第一轮有错，修正后全对）

**卡住的地方**：

```
1. 练习2 严重程度判断第一版错了2条：
   - IE11表格错位标了"一般"→应为"轻微"（UI瑕疵功能正常=轻微，不是"不影响主功能=一般"）
   - 验证码加载失败标了"轻微"→应为"一般/中"（注册必经环节受阻≥一般，刷新可恢复只是从严重降到一般）
   → 核心教训：轻微=UI/文案瑕疵且功能完全正常；验证码是核心环节不能算瑕疵
2. 练习3 改标题第一版写了5条模板（"某某模块+报错信息"）而不是具体标题
   → 理解了公式结构但没落地。修正后每条都有真实模块名、操作、现象
     （如"[商品搜索] 连续快速搜索5次后页面崩溃白屏"）
3. 练习1 bug报告的复现步骤顺序有误：选完"1"后直接回车再输标题
   → 正确顺序：选1→输入标题→回车确认→q→回车退出→重开
```

**学到的规律**：

```
- 严重程度看"坏了多严重"（测试定），优先级看"急着修不"（产品定），两者经常不对等
- 官网错别字=轻微+高优；冷门报表数据错=严重+低优
- Bug标题公式：[模块] + 操作/输入 + 异常现象。只看标题就要知道哪里坏了
- Bug报告八要素缺一不可，尤其环境和附件——开发复现不了=白提
- 生命周期口诀："新指修验关"（主流程）+"拒延重"（异常分支）
```

**面试能用**：

- "Bug生命周期包括新建、指派、修复中、待验证、关闭五个主状态，以及拒绝、延期、重新打开三个异常分支。严重程度看破坏程度分致命/严重/一般/轻微，优先级看紧急度分高/中/低，两者由不同角色从不同角度判断，经常不对等"
- "Bug报告必须包含标题、环境、前置条件、复现步骤、实际结果、预期结果、严重程度+优先级、附件八个要素。标题用'模块+操作+现象'公式写清楚"
