# 2026-11-24（W3 Day7 · 登录用例综合实战）


**做了什么**：产出 `test-design/登录功能测试用例.xlsx`（35 条实写用例 + 等价类划分表 + 待补充-W4 占位 7 条）+ `bug报告示例.md`；四个 sheet：规格说明/测试用例/等价类划分表/待补充-W4

**卡住的地方**：

```
1. 表格一开始转置了（要素在行、用例在列），写到14条才转成标准方向
   → 教训：建表第一步就定好"一行一条用例"，越晚转成本越高
2. 安全性维度一开始写不出来——SQL注入/抓包/越权这些知识没学过
   → 调整：拆成"今天能写的UI层8条"+"W4占位7条"。错误推测法的前提是有经验，
     没学过的知识不能硬编。锁定机制4条（第4次/第5次/锁定中/解锁后）其实就是判定表
3. token 不知道是什么 → 学了"通行证"类比：登录发凭证，之后每次请求带着，退出要作废。
   用例从用户可见行为写（退出后直接输/home网址），不用管底层
4. Excel 三个坑：开头单引号被吃（设文本格式）、深色界面粘贴带白字格式（Ctrl+Alt+V只粘值）、
   文件被WPS占用脚本写不进（关进程释放锁）
5. 多次修改忘保存，AI读到的还是旧文件 → 改完必须Ctrl+S再让人检查
```

**学到的规律**：

```
- 用例去重是设计的一部分：输入校验重复模板不硬凑，用等价类划分表声明覆盖，代表值执行
- 兼容性一环境一条用例，混在一条里无法单独标记失败
- 时间相关用例（7天过期/30分钟锁定）备注模拟手段：改系统时间或后端缩短有效期
- 规格没定义的行为（同账号互踢）预期写"按产品策略执行"+备注"待确认"，不编造
- 预期结果不能抄标题："提示位置明确"不可判定，要写"XX提示显示在XX框下方"
- 测试计划分批是正常的：依赖什么知识就排到什么阶段，占位sheet展示完整性
```
