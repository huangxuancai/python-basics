# 2026-11-27（W4 Day2 · 状态码全家桶）


**做了什么**：跑通 `day14_practice.py` 本地靶场（16 个状态码全触发，自检 18/18 PASS）+ `status_code_drill.txt` 存档；做 403→200 附加实验，亲眼看到自检报 `FAIL GET /403 期望 403 实际 200`，存档留为 `status_code_drill_越权实验.txt`；口头四问答对 3.5/4

**卡住的地方**：

```
1. 504 一开始判成"网关的锅" → 错。504 是网关报的码，但根因在后端太慢
   （慢SQL/死循环/下游依赖卡住），网关只是"等太久帮你报信"的那个人。
   排查方向不是查网关配置，是查后端耗时。500/502/504 的区别不是"谁报的码"，
   是"链路上哪一段断了"：代码崩 / 后端不在 / 后端慢
2. 附加实验做完只把代码改回来了，忘了重跑 → 存档里留的还是漏洞版（17/18），
   差点让验收误判靶场有问题。
   教训：实验类改动要"代码+产物"一起复原，只改回代码不算复原
3. 403 实验看到那一行 FAIL 时才有实感：17 项绿、1 项红，人眼扫一遍根本发现不了
   "403 变 200"，断言一秒抓出来。这就是接口自动化的价值，不是跑得快
```

**学到的规律**：

```
- 状态码先记"锅在谁"再记具体码：2xx 无事、3xx 服务器指路、4xx 客户端、5xx 服务端
- 401 vs 403 判定法：重新登录能不能解决？能→401，不能→403
- 301 的坑不在"跳转"，在"浏览器会长期缓存这个永久规则"——发错等于事故，临时跳转一律 302
- 200 ≠ 业务成功：HTTP 层说"通信成功"，业务层说"事情办成没办成"，两个维度。
  断言必须 状态码 + 业务码 + 关键字段 三件套
- 越权漏洞的报文长相：本该 403 的接口返回 200 + 别人的数据。测试时"期望 403 实测 200"就是缺陷
- 无 body 的响应不能解析：204 / 304 无脑 r.json() 会抛异常，这是 DELETE 接口必测项
```

**面试能用**：

- "状态码我按'锅在谁'理解：4xx 是客户端问题，5xx 是服务端问题。三组易混我都掰过——401 是没认证、403 是认证了没权限，判据是重新登录能不能解决；301 会被浏览器长期缓存所以临时跳转必须用 302；500 是应用代码崩、502 是网关拿不到后端、504 是网关等后端超时但根因在后端慢，三者排查方向完全不同"
- "我用本地靶场复现过越权漏洞：把一个该返 403 的接口改成返 200 加别人的订单数据，自动化断言立刻报 '期望 403 实际 200'。这让我理解了接口自动化的价值不是跑得快，是人眼会漏、断言不会"
- "200 不代表业务成功。登录失败经常返 200 加业务码 50001，所以我的断言是状态码、业务码、关键字段三件套一起断"
