# 2026-11-22（W3 Day5 · 用例要素）


**做了什么**：学习用例十要素、预期结果可判定原则、前置条件vs操作步骤区分、优先级P0-P3定义、编号规范；四个练习全做并验收通过（第一轮有错，修正后全对）

**卡住的地方**：

```
1. 练习 1 第一版 TC-REG-001 操作步骤复制残留（多了"点击登录按钮"和孤立的"钮"），
   预期结果写"注册成功"不可判定
   → 修正：步骤清理为三步，预期改为"页面跳转到 /login，显示'注册成功'提示"
2. 练习 3 三条 todo.py 用例的前置条件全写成了操作步骤
   （"已输入1选择添加"是动作不是状态）
   → 修正：统一改为"todo.py 已运行，处于主菜单界面"
3. 练习 4 优先级排序第一版只对 2/8 条
   → SQL 注入排了 P3（应为 P1）、placeholder 排了 P0（应为 P3）
   → 核心教训：安全相关永远 P1 以上，UI 细节永远 P3，只有核心主流程才配 P0
```

**怎么解的**：

```
1. 写完用例后逐字检查步骤，确认没有复制残留
2. 前置条件自检：有动词就是步骤，改成"已有/已处于"的状态描述
3. 优先级判断口诀：P0=没它不能上线，P1=重要功能/安全，P2=有替代方案，P3=UI细节
```

**学到的规律**：

```
- 预期结果的判据：让陌生人看，能不能不问任何问题就判定通过/失败？能=合格
- 前置条件是"假设"，操作步骤是"动作"。有动词大概率写错了
- 优先级不看"常见不常见"，看"后果严不严重"。SQL注入不常见但后果致命=P1
- 用例编号 TC-{模块}-{序号} 不是形式主义，是沟通/追溯/自动化的基础
- 第一版出错很正常，改对才是学习。Day5 四个练习都是改后才通过的
```

**面试能用**：

- "一条好的测试用例包含编号、模块、标题、优先级、前置条件、测试数据、操作步骤、预期结果等要素。其中预期结果最关键，必须唯一且可判定——写'登录成功'不合格，要写'跳转到 /home 且右上角显示用户名'。前置条件是状态不是动作，操作步骤要编号且原子化"
